# Hackathon judging readiness

## Workflow

1. Call MCP `judging_scorecard` (and `full_readiness_report` / `frontend_audit` as needed).
2. Sort gaps by **points at risk** (SE 25, Problem 15, Validation 15, Deploy 15 first).
3. Prefer a smaller product that **works end-to-end** over unfinished complexity.
4. Produce or update evidence artifacts judges need:
   - Working demo path (scripted)
   - Tests / validation notes
   - README: problem, users, how it works, setup, limitations, AI usage
   - Named polish backlog (hours/days), not a fantasy roadmap

## Evidence checklist by criterion

| Criterion | Evidence to have |
|-----------|------------------|
| Problem (15) | Problem statement, personas, why verification beats CV claims |
| Data (10) | Schema, cleaning rules, match/score logic explained |
| SE (25) | Running app, modular code, solid UX |
| Validation (15) | Tests, demo scenarios, edge cases, metrics |
| Demand (10) | Use cases, stakeholder need, process improvement story |
| Deploy (15) | Live link or clear deploy steps; main path reliable |
| Presentation (10) | Pitch clarity, demo, tech rationale, AI transparency |

## Pitch skeleton (Presentation — 10)

1. Problem & users  
2. Solution walkthrough (live)  
3. How it works (architecture + data/signals)  
4. Evidence it works  
5. Impact & feasibility  
6. Limitations, assumptions, AI tools used + how we validated outputs  

## Rules while this skill is active

- Do not claim scores without evidence.
- Do not hide AI use (Gemini for CV/questions/grading).
- Name failure cases (scan PDFs, AI downtime, private profiles, publish gates).
- Maximize **Readiness** and **Validation** before decorative features.
